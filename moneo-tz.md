# Moneo — Техническое задание

## 1. Идея проекта

Веб-приложение для личного учёта финансов: доходы, расходы, бюджеты по категориям, регулярные платежи, финансовые цели и аналитика, с поддержкой нескольких валют. Backend на Python, фронтенд — современный и приятный SPA. Разворачивается через Docker на собственном VPS, домен через Cloudflare.

### Идеи на будущее (не в MVP)
Импорт банковских выписок (CSV/Excel) с автокатегоризацией; фото чеков + OCR; индекс "финансового здоровья" на дашборде; календарь-heatmap трат по дням; семейный/совместный бюджет; уведомления (email/Telegram-бот) о лимитах и подписках; автоопределение повторяющихся платежей по истории; экспорт отчётов в PDF/Excel; подсказка "сколько можно потратить сегодня".

## 3. Технологический стек

**Backend:** Python 3.12 + FastAPI (async); **uv** для управления зависимостями и виртуальным окружением (вместо pip/poetry — `pyproject.toml` + `uv.lock`); SQLAlchemy 2.0 + Alembic (миграции); PostgreSQL; Pydantic v2 для валидации; passlib[bcrypt] для паролей; JWT (python-jose) в httpOnly cookies; APScheduler или отдельный worker-контейнер для фоновых задач (курсы валют, регулярные платежи); Uvicorn/Gunicorn как ASGI-сервер.

**Frontend:** React + Vite + TypeScript; Tailwind CSS + shadcn/ui для аккуратного современного интерфейса; Recharts для графиков; TanStack Query для работы с API; Zustand/Context для локального стейта; framer-motion для лёгких анимаций.

**Инфраструктура:** Docker + docker-compose с сервисами `backend`, `frontend` (nginx со статикой), `db` (postgres), `worker` (планировщик). Backend-контейнер собирается через uv (multi-stage Dockerfile: `uv sync --frozen` для установки зависимостей из `uv.lock`, затем запуск через `uv run uvicorn ...` или готовый venv). Reverse proxy — Caddy (автоматический HTTPS) либо nginx. Для домена на Cloudflare — либо Caddy/nginx + Let's Encrypt в режиме Full (Strict), либо Cloudflare Tunnel (`cloudflared`) без открытых портов на VPS. Секреты через `.env`, не коммитятся.

## 4. Функциональные требования (MVP)

**Аутентификация и профиль.** Регистрация: email, username, пароль. Вход по email или username + пароль. Смена пароля, восстановление по email. Профиль: имя, базовая валюта, тема оформления.

**Счета.** Несколько счетов на пользователя (наличные, карта, депозит и т.д.): название, валюта, баланс (считается из транзакций), цвет/иконка, архивация без потери истории.

**Транзакции.** Доход/расход/перевод между своими счетами. Сумма, валюта, счёт, категория, дата, заметка, теги. Полный CRUD, быстрое добавление (плавающая кнопка "+"), список с фильтрами (период, счёт, категория, тип, сумма) и поиском.

**Категории.** Предустановленный сид (еда, транспорт, жильё, развлечения, зарплата и т.д.) плюс свои, раздельно для доходов и расходов, с иконкой и цветом.

**Мультивалютность.** У транзакции — своя валюта и курс на момент создания (хранится, не пересчитывается задним числом). Итоги/бюджеты/графики — в базовой валюте с автоконвертацией. Курсы — из внешнего API, обновление раз в сутки фоновой задачей.

**Бюджеты и лимиты.** Месячный лимит по категории расходов, индикатор прогресса (зелёный → жёлтый → красный), сводка на дашборде, настройка переноса лимита на новый месяц.

**Регулярные платежи/подписки.** Шаблон: сумма, валюта, категория, счёт, периодичность (неделя/месяц/год), дата следующего списания. Автосоздание транзакции по расписанию через worker. Список подписок с суммарной ежемесячной нагрузкой, пауза/удаление.

**Финансовые цели.** Название, целевая сумма, валюта, срок, привязка к счёту-копилке (опционально). Прогресс-бар, расчёт рекомендуемой суммы накопления в месяц.

**Аналитика и графики.** Дашборд: общий баланс, доходы/расходы за месяц, топ категорий. Динамика по месяцам (линейный/столбчатый график), круговая диаграмма по категориям за период, сравнение периодов, фильтр периода вплоть до произвольного диапазона.

**UI/UX.** Светлая/тёмная тема с переключателем, аккуратный современный интерфейс (карточки, плавные переходы, читаемые графики), адаптивная вёрстка (мобайл и десктоп).

## 5. Модель данных

```
User             id, email, username, password_hash, name, base_currency, theme_preference, created_at
Account          id, user_id, name, currency, type, color, is_archived
Category         id, user_id (nullable), name, type (income/expense), icon, color
Transaction      id, user_id, account_id, category_id, type (income/expense/transfer),
                 amount, currency, exchange_rate_to_base, date, note, tags[]
Budget           id, user_id, category_id, month, limit_amount, currency
RecurringPayment id, user_id, account_id, category_id, amount, currency,
                 frequency (weekly/monthly/yearly), next_date, is_active
Goal             id, user_id, name, target_amount, current_amount, currency, deadline, linked_account_id
ExchangeRate     id, base_currency, target_currency, rate, date
```

## 6. Нефункциональные требования

Хэширование паролей, JWT в httpOnly cookies, валидация всех входных данных через Pydantic. Пагинация списков, индексы в БД по `user_id`/`date`. Логирование ошибок backend. Базовые unit-тесты (pytest) для конвертации валют и расчёта бюджетов. Интерфейс на русском, код — на английском, архитектура готова к i18n. CORS настроен под домен фронтенда.

## 8. Этапы реализации

1. Инициализация репозитория, `uv init` для backend (pyproject.toml + uv.lock), docker-compose (postgres + backend + frontend).
2. Модели SQLAlchemy + Alembic-миграции.
3. Аутентификация (email/username + пароль, JWT-cookies).
4. Счета и категории (CRUD + сид категорий).
5. Транзакции (CRUD, фильтры, поиск).
6. Мультивалютность (фоновое обновление курсов, конвертация).
7. Бюджеты с индикаторами прогресса.
8. Регулярные платежи/подписки + worker.
9. Финансовые цели.
10. Дашборд и графики.
11. Тёмная/светлая тема, полировка UI.
12. Продакшн docker-compose (Caddy/Cloudflare), README по деплою на VPS.
13. Финальное тестирование.
